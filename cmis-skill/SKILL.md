# CMIS — 演唱会文创决策辅助系统 v5.5

## 核心理念

> 将艺人的情绪价值、演唱会体验、城市文化与粉丝消费心理，转化为**可核算、可落地**的情绪消费产品系统。

本系统不是"给艺人做周边"，而是一套**商业决策引擎**。任何一份方案必须能回答五个问题：

| 问题 | 对应输出 |
|------|---------|
| 他是谁、谁在买？ | **依据七册 D1-D4**：艺人档案 / 粉丝圈层 / 情绪地图 / 城市场馆 |
| 能不能做成？ | **依据 D5** 经纪公司与授权链（决策链/审批周期/合同范围） |
| 值不值得做？ | **依据 D6** 自有IP生态与分流 + Gate A 立项判定 + 圈层类型 + 规模档位 |
| 做多少？ | 市场容量测算 + 分SKU首批量 + 毛利/盈亏平衡 |
| 来不来得及做？ | 授权倒排 + 交期倒排 + 合规否决清单 |
| 具体做成什么？ | **依据 D7** 品类与趋势 + 符号推导 + SKU矩阵 + 设计执行包 |

只回答"做什么好看"的方案，视为不合格。**直接从产品讲起的方案，同样不合格**——它没有告诉客户"我凭什么这么判断"。

## 三个历史反例（v5.3 新增，每次执行前先读一遍）

这三件事提醒我们：**演唱会文创的成败，往往不由创意决定。**

| 案例 | 表面现象 | 真实原因 | 对应机制 |
|------|---------|---------|---------|
| **周杰伦**（顶流，定制款却卖不过别人） | 门票溢价极高、数万人到场，伴手礼销售反而不如同量级艺人 | 经纪公司 IP 管理与授权链混乱，临近演出仍未定案 → 设计与生产被压到不可行 | 组织与授权可行性（3-15分）+ 授权倒排 + Gate A 合作确定性 |
| **赵雷**（民谣，预测低却爆了） | 听众保守收敛，事前不被看好；实际棒球帽、钥匙扣大卖并连补货，演后一月仍有"戒断反应" | 把"不喧哗"误读为"不消费"；应援类失效、**日常配饰**承接需求；**长尾远长于流行歌手** | 圈层类型（创作/民谣型）+ 结构修正 + 长尾系数 λ 1.3-1.6 |
| **谢霆锋**（大牌，定制款平平） | 自带汉堡、饮料、T恤、方巾进场，鸟巢定制款销售平平 | **同场景、同预算、同品类的现场竞争**，叠加自有品牌长期渠道 | 分流来源 E（现场自带）+ 现场修正 0.85-1.0 |

> 结论：**先问"能不能做成"，再问"卖不卖得动"，最后才问"做成什么样"。** 顺序反了，方案再漂亮也没用。

## 标准输入结构

```yaml
artist_name:      # 艺人/组合名称（必填）
concert_date:     # 演唱会日期（必填——决定交期倒排与交付深度）
concert_city:     # 举办城市
concert_venue:    # 场馆名称
concert_name:     # 演唱会名称（可选）
show_count:       # 场次数（可选，默认1场；直接影响容量测算）
seats:            # 单场可售座位数（可选，缺省按场馆额定座位×0.9）
budget_range:     # 文创预算范围（可选，影响SKU结构与工艺上限）
target_sku_count: # 期望SKU数量（可选，默认8-12个）
authorization:    # 授权状态（可选：已签约/谈判中/未接触；缺省按"未接触"处理，会触发授权风险提示）
```

缺省处理：**不要停下来反问基本信息**。城市/场馆缺失时按"巡演通用"处理；场次缺失按1场并标注；日期缺失则**跳过交期闸门的硬判定**，仍输出标准工期表供倒排。

## Layer 0｜项目分诊（收到输入后先做，30秒内完成）

在展开7层分析前，先判定**项目档位**与**交付深度**。同一套方法在距演出60天和16天时，输出完全不同。

### 0.1 距离演出天数 D-day

```
D-day = 演唱会日期 − 今日
```

### 0.2 项目档位（规模档）

| 档位 | 判定条件 | SKU数 | 默认结构 |
|------|---------|-------|---------|
| **S 小规模** | 单场 ≤2万座 / 首次合作 / 预算有限 | 5-7 | 引流3 + 利润2 + 品牌1 + 稀缺1 |
| **M 标准** | 单场 2-5万座 / 成熟巡演 | 8-11 | 引流3 + 利润4 + 品牌2 + 稀缺2 |
| **L 大型** | 体育场 ≥5万座 / 多场连开 / 头部艺人 | 12-16 | 引流4 + 利润5 + 品牌3 + 稀缺3 |

### 0.3 交付深度（由 D-day 决定，必须遵守）

| D-day | 交付模式 | 输出要求 |
|-------|---------|---------|
| **≥60天** | 全案 | 18章完整输出（依据 D1-D7 全量）+ Top3 单品完整设计执行包 + 其余SKU一页卡 |
| **30-59天** | 标准案 | 18章输出，依据册压缩至每册≤1页，供应链章节给出"锁货优先级"，执行包降为 Top2 |
| **15-29天** | 精简案 | 依据只留 D1 1页 + D2 参数与禁区 + D3 段落表 + D4 档期 + D5 结论；省略长尾，必出交期倒排 + 现货改装方案 |
| **<15天** | 急救案 | 依据留 D1 半页 + D2 参数 + D3 段落表 + D4 档期 + D5 一行授权状态；只做四件事：①必保品类清单 ②现货/半定制替代方案 ③演后预售结构 ④现场陈列与限购机制 |

> ⚠️ 交付深度是**硬约束**。在 D-day < 30 天时仍输出完整设计执行包，是对客户时间的浪费，也是不专业的表现。必须在方案开头明确写出"本次为XX案，因距演出仅X天"。
> ⚠️ 但**依据不能因为时间紧就删光**：时间越紧，越只能靠依据做判断，因为没有试错空间。

### 0.4 两个前置修正（v5.3）

**修正一：授权未落地时，D-day 要重算。**

```
有效可执行天数 = 预计拿到书面授权日 − 今日 − 留白（8-10天）
```

若授权仍在谈判，按"授权周期中位数 30-45 天"倒推；实际可用天数往往比 D-day 短得多。
周杰伦案例的本质就是：D-day 看起来有 60 天，**有效可执行天数只有 15 天**。

**修正二：先判圈层类型，再定参数。**

同一套漏斗公式，民谣/摇滚/唱将型的 `w`、`s`、`λ` 与流量偶像完全不同。
在 Layer 1 完成圈层判定（见 `artist-archetypes.md`），否则后续测算全错。

## 执行流程

```
Layer 0   → 项目分诊（档位 + D-day + 交付深度）
Layer 1   → 数据采集（产出依据 D1 艺人档案 + D2 粉丝圈层与审美权重，含符号词库/禁用黑名单/平台分布）
Layer 1.5 → 经纪公司与授权链（D5）+ 自有IP生态与分流率（D6）→ Gate A 立项闸
Layer 2   → 演唱会情绪系统与篇章结构（D3）
Layer 3   → 城市/场馆/IP权重与档期结构（D4）
Layer 4   → 品类发现与趋势洞察（D7，三维框架）
Layer 5   → SKU决策（符号推导 → 矩阵 → 评分 → Gate B 定量闸）
Layer 6   → 落地校验（交期倒排 + 合规清单 → Gate C 可行闸）
Layer 7   → 创意生成与运营方案
```

> D1-D7 必须先全部落纸，才能进入 Layer 5 选品。依据册的字段、验收标准、编号规则与反模式见 `references/decision-basis.md`。

详细执行规范见 `references/layers.md`。

## 三道闸门（核心机制）

CMIS 与普通策划工具的区别，在于**每个阶段都有否决权**。任一道闸门亮红，必须调整方案，不得强行通过。

### Gate A｜立项闸（Layer 1.5 后）

> 此处用**快速预估**的艺人IP强度（国民度/票房/粉丝规模，1-10分）；Layer 3 会正式评分，若差异≥2分，以 Layer 3 为准并回头修正 Gate A 结论。

| 判定 | 条件 | 动作 |
|------|------|------|
| 🟢 可做 | IP强度≥6 且 分流率≤中 | 按档位正常产出 |
| 🟡 需调整 | IP强度 4-5 或 高分流 | SKU数下调一档，强化限定专属元素，k 取 0.6-0.75 |
| 🔴 慎做 | IP强度≤3 或 极高分流 | 只做低风险刚需品（票根套/贴纸/T恤），或明确建议"本场不做重投入" |

**并行的第二判断——合作确定性**（组织与授权评分 3-15 分，见 `artist-ip-ecosystem.md`；档案与合同细节见 `agency-authorization.md`）：

| 评分 | 等级 | 对 Gate A 的影响 |
|------|------|-----------------|
| 12-15 | 🟢 稳定 | 不影响 |
| 8-11 | 🟡 有摩擦 | 交付模式**至少降一级**，全流程预留 15-20 天授权缓冲 |
| 3-7 | 🔴 高风险 | 不论 IP 多强，一律按"不开模 + 现货改装 + 演后预售"设计，并书面提示"最大风险是做不出来" |

> 周杰伦案例即 🔴 型：IP 强度满分，但合作确定性极低，最终交付能力被压缩到不如中腰部艺人。

### Gate B｜定量闸（Layer 5 后）

每个SKU必须同时满足：**预测销量 ≥ MOQ**、**毛利率 ≥ 象限下限**、**售罄率预估 ≥ 60%**。
不满足 → 调整定价/工艺/数量，或降级为"演后预售款"，或直接剔除。

### Gate C｜可行闸（Layer 6 后）

授权、交期、合规、预算四项任一为红 → 该SKU必须替换或改为演后发货模式。
**Gate C 是最容易被忽略、也最容易让整份方案作废的一关**（参考：LED应援棒取决于场馆安检，纪念章标准工期 45-60 天，周杰伦案则卡在授权）。

## ⚠️ 核心原则一：分流率思维（Diversion Rate）

> 这是本 Skill 区别于一般周边策划工具的关键。

**任何艺人都不是"裸IP"**。在筹备演唱会限定周边之前，必须先回答：

> 这位艺人本身有多少"长期、稳定、低门槛"的官方/个人IP消费渠道？这些渠道会分流多少粉丝的购买力和购买意愿？

### 典型场景对比

| 艺人画像 | 自有IP生态 | 对演唱会限定款的影响 |
|---------|-----------|---------------------|
| **谢霆锋型** | 自有餐饮品牌（锋味）+ 常规文创 + 长期抖音直播带货 + **自带货进场**（汉堡/饮料/T恤/方巾） | 购买渠道高度分散且常态化，**同场还被自己的货抢**，实际转化率明显偏低 |
| **五月天型** | 阿信个人IP经营成熟，五球毛绒等长期在固定渠道销售 | 经典符号已被"日常化"，限定款若雷同会被视为"换皮重复购买" |
| **周杰伦型** | 自有IP极强，但授权链混乱、多供应商并存 | 问题不在分流，而在**根本来不及做**（见组织与授权可行性） |
| **新人/纯演唱会型** | 几乎无自有IP消费场景 | 分流率低，限定款是情感的**唯一/主要出口**，转化率天然更高 |

### 五个分流来源（v5.3 补充 E）

| 来源 | 说明 | 作用方式 |
|------|------|---------|
| A 自有品牌 | 餐饮/潮牌等跨界实体 | 分散情感消费预算 |
| B 长期常规文创 | 官方店铺常驻款 | 符号"日常化"，复购动力下降 |
| C 直播带货 | 常态化电商 | 养成"等直播"习惯，现场原价敏感 |
| D 历史限定通货化 | 历年设计高度相似 | 稀缺感自我稀释 |
| **E 现场自带产品** | 艺人自有餐饮/服饰进场设摊、赞助商赠品 | **同场景同预算直接竞争**，`k` 再乘 0.85-1.0 |

### 分流率怎么用（v5.2 修正）

分流率 **不是** 简单地把首批数量乘以一个系数（旧版做法会导致与容量测算重复打折）。正确用法：

> **分流率作用于"购买意愿率 w"，再传导到销量与首批量。**

```
现场销量 Q = N(有效观演人次) × w(整体购买意愿) × k(分流率系数) × s(品类份额) × e(情绪系数)
总需求   T = Q × λ(长尾系数，按圈层 1.0-1.6)
```

详见 `references/quant-model.md`。文字结论与数字结论必须一致，不能出现"文字说保守、数量却按乐观算"。

### 分流率对策略的四个影响

1. **差异化优先于雷同**：限定款须与艺人现有长期产品在**品类、视觉符号、材质工艺**上明显区分
2. **量化下调预测**：高分流 → k 取 0.6-0.75；极高分流 → k 取 0.4-0.6（作用于意愿率，不是砍量）
3. **强化"限定专属价值"**：编号、日期、场馆专属元素层级可适当上调
4. **渠道协同而非对立**：强势直播渠道可做"限定编号 + 直播间补货"组合

## 核心原则二：符号驱动，而非品类驱动

**造成"所有艺人产品都很像"的根本原因**：先想品类（T恤/钥匙扣/徽章），再往里塞艺人元素。

正确路径是反向的——从 Layer 1 的「专属符号词库」出发，问：

> **"这个符号/情绪/意象，最适合被做成什么形态的产品？"**

实证支撑见 `references/empirical-data.md`：跨 6 位艺人 56 个 SKU，高差异化产品全部来自"符号→形态"推导（五球→拼图冰箱贴、磁带→异形钥匙扣、八花→毛绒挂件、快乐→NFC/发声罐）。

---

## 核心原则三：圈层不同，模型不同（v5.3）

> 赵雷的教训：不是"民谣粉丝更爱买"，而是**用对了品类**。

| 圈层 | 关键差异 | 若不修正会怎样 |
|------|---------|--------------|
| 创作/民谣型 | 日常配饰（帽/钥匙扣/包）强，应援类弱；λ 1.3-1.6 | 押注应援棒+T恤 → 结构错配、长尾漏算 |
| 摇滚/独立型 | 反"塑料感"，重平面与工艺；λ 1.2-1.4 | 做廉价塑料件 → 口碑反噬 |
| 流量偶像型 | 应援类与小卡主导，现场即峰值；λ 1.0 | 押注长尾 → 库存积压 |
| 资深唱将型 | 重决策、客单价高、礼盒强 | 做过量低价小件 → 毛利不足 |

圈层判定与参数表见 `references/artist-archetypes.md`；参数落地见 `quant-model.md`。

> 一句判断法：**粉丝用什么方式表达爱，就用什么形态承载。** 举灯牌的表达 → 应援类；不发朋友圈但会日常戴 → 配饰类。

## 最终输出结构（18章 · 依据 → 决策 → 落地）

> **写法铁律：先取骨架，再填内容。** 每章的表格列头、必填格子以 `references/templates.md` 为准，逐格对照 `references/field-registry.md` 的验收标准填写。**不要凭记忆重新设计表格**——历史上每一次"漏字段"都发生在临时发挥的时候。
>
> **铁律：第 1 章之后到第 9 章之前，只许写依据，不许出现具体 SKU 提案（款式命名、定价、配额）。** 品类方向与工艺方向可以出现——依据本来就要指向品类。先讲清"他是谁、谁在买、那一夜会发生什么、谁能签字"，再谈具体产品。

### 第 1 章 决策摘要（一页纸，唯一允许结论前置的地方）

结论的每一行都必须挂依据编号 `[D2-03]`；无编号的结论最多 3 条且须标「⚠️ 无依据，属判断」。

### Part I｜决策依据（D1-D7，第 2-8 章）

## 关键判断原则

1. **情绪优先于功能**：演唱会文创的核心是情绪消费，不是实用消费
2. **艺人专属符号优先**：所有SKU必须建立在「专属元素词库 + 禁用黑名单」之上，元素来源：近3年巡演视觉沉淀、音乐内容沉淀、个人人设特质、独有标志性符号
3. **审美准确是生死线**：当下粉丝偏好极简暗纹、低饱和高级色、浮雕肌理、低调刻印，排斥廉价卡通风和夸张大LOGO
4. **场馆元素要克制**：除场馆本身有极高IP价值，场馆元素应作为隐性细节而非主视觉
5. **城市适配不可忽略**：北京、上海、成都、广深的消费偏好差异显著
6. **当下热点必须结合**：SKU必须结合艺人当前情绪热点，而非历史标签
7. **分流率必须量化**：自有IP生态越成熟，越要做"差异化+不可复制"，预测越保守
8. **高级稀缺性是竞争壁垒**：行业90%供应商只做印花/印LOGO/印歌词；声纹暗纹、隐藏彩蛋、唯一编号、差异化工艺是方案通过审核的核心竞争力
9. **数字必须自洽（v5.2新增）**：容量、转化率、单价、毛利、首批量之间必须能对上账；每个假设标注依据与置信度，不允许出现"结论A、数字B"
10. **交期与合规是硬约束（v5.2新增）**：再好的创意，来不及做或过不了安检，等于零
11. **先看授权，再看创意（v5.3新增）**：IP 管理混乱、审批链不清的艺人，方案要按"做不出来"来设计，而不是按"卖不动"来设计
12. **圈层决定结构，不是总量（v5.3新增）**：预测错了先查品类结构与长尾，别急着调总量；民谣/摇滚/唱将型不得套用流行歌手矩阵
13. **把艺人自己的货算进来（v5.3新增）**：调研联名的同时，必须盘清艺人自带的餐饮/服饰/摊位——同场竞争比场外分流更致命
14. **长尾是生意的一部分（v5.3新增）**：λ>1.2 的项目必须写返单与演后运营，否则等于主动放弃 20-35% 销量
15. **先立依据，再谈产品（v5.4新增）**：方案前半部必须是"人、粉丝、那一夜、那座场馆、那个签字的人"，否则后半部所有数字都无出处。**依据部里出现具体款式与定价，就是流程倒置**（品类与工艺方向不算）。
16. **字段有总账，交付有校验器（v5.5新增）**：18 章共 **170** 个必填格子（另加 12 条跨章一致性约束），靠记忆一定漏。写前照 `field-registry.md`，写后跑 `tools/cmis_check.py`，**0 FAIL 才算完成**
17. **冲突时降假设，不降结构（v5.5新增）**：总量与结构对不上时（如人均件数算不拢），优先保留有实证锚定的结构比例，调整 C 级假设的总量参数——反过来做会把每一款都推到实证区间之外
18. **依据必须可追溯、可引用（v5.4新增）**：每条依据带编号（D1-01…），关键数字标 A/B/C 置信度，且 C 级占比 ≤30%；没被第 1 章或第 9 章引用过的依据要删掉——那是背景材料，不是决策依据

## 交付前机械自检（v5.5 新增，硬性）

写完不算完。**必须跑一次校验器，FAIL 清零才能交。**

```bash
python cmis-skill/tools/cmis_check.py cases/你的方案.md
```

它查的是人最容易糊过去的地方（对应 `field-registry.md` §19 的一致性矩阵）：

| 检查 | 拦什么 |
|------|--------|
| 章节完整性 / 三段式 | 少写一章、依据与决策混在一起 |
| 每册「决策含义」+「我们不知道什么」 | 依据写成百科搬运、只写有利面 |
| 依据编号定义 ⊇ 引用 | 悬空引用、整册未被引用（=白写） |
| 审美权重合计 = 100% | 凭感觉分配百分比 |
| Σ 份额 = 100% | 结构比例不闭合 → 总件数与人均件数同时错 |
| 人均件数 = Σ销量 ÷ 决策人次 ∈ 1.6-2.6 | 模型自设校验线被违反（曾算出 0.43 件/人） |
| 毛利率 =（售价−完全成本）÷售价 | 只算出厂价 → 毛利虚高 25-30 点 |
| 限量款销量 ≤ 限量数 | 超限量发售（曾超 3.4 倍、虚增 241 万） |
| 分波去化合计 = 100% | 有一批货没有出口 |
| 依据部（2-8 章）无品牌化 SKU 名 | 先有结论再找理由 |
| 极限词（绝版/永不再有/最后机会） | 广告法风险；禁用清单语境自动豁免 |
| 附录 A/B/C + Top3 三段执行包 | 交付出不了手 |

WARN 不阻塞交付，但必须逐条给理由：**机械层保证"不漏"，人工层保证"不假"。**

## Web Search 指引

执行过程中**必须使用 web search** 获取以下实时信息：

- 艺人最近热搜、争议、爆火内容（微博/小红书/抖音）
- **近3年巡演视觉风格、舞台设计、主色调变化**
- 本场演唱会官宣信息、主视觉、**篇章/章节结构**、**场次结构（首场/生日场/末场/加场）**、票价档位
- **官方粉丝名称、官方应援色/应援物**（没有就写"无"——"无"本身就是设计约束）
- **生涯里程碑与周年节点**（出道/成立年份、代表作发行年、上一次同级别场馆的表现）
- **粉丝平台分布与社群生态**（超话、小红书话题、抖音话题、后援会组织形态）
- 城市消费数据与文娱消费习惯
- 当前文创行业爆款趋势与在售同类产品价格
- **艺人自有品牌/文创产品线及销售渠道**
- **艺人自带货与现场摊位情况**（自有餐饮/服饰是否进场、赞助商赠品）
- **该艺人经纪公司/工作室的授权与合作口碑**（是否有临期才定案、多供应商并行的历史）
- **该艺人往届演唱会限定周边的实际销售反馈与价格**
- **场馆安检政策与禁限带物品清单**（涉及LED/电池/激光/充气类产品）

不可仅依赖训练数据——"当下情绪""艺人自有渠道现状""场馆政策"都是核心变量且会变。
