# CMIS 字段总账（Field Registry）

> **本文件是单一事实源（Single Source of Truth）。**
> `layers.md` 讲"怎么分析"，`decision-basis.md` 讲"依据的逻辑与验收"，本文件只做一件事：**把一份合格方案必须出现的每一个格子列全，并写明怎么判定它没被漏掉。**
>
> 写方案时逐章对照本表；交付前跑 `tools/cmis_check.py` 做机械校验；两者都过，才算完成。
>
> **规模：18 章 · 179 个格子 · 13 条跨章一致性约束（C1-C13）。** 各章数量：14 / 21 / 16 / 11 / 12 / 14 / 12 / 10 / 13 / 9 / 7 / 6 / 5 / 5 / 9 / 5 / 5 / 5。
> v6.0 新增 4 格：2-20 符号系统四参、2-21 符号判定依据、9-11 可替换性检验、9-12 入门件确认。
> v6.1 新增 4 格：1-14 价值捕获结论、7-11 并行售卖主体清单、7-12 V 四分量计算表、9-13 价格带覆盖确认；新增 C13 与 §24。

---

## 0. 使用方式（三步）

1. **动笔前**：按第 1 章 → 第 18 章顺序，把本表对应章节的字段列抄成本地清单（或直接用 `references/templates.md` 的空表骨架）。
2. **写每章时**：字段一条不能省；写不出来的写"待补 + 为什么补不到 + 用什么替代判断"——**空着不写是最差的做法，写"待补"至少诚实**。
3. **交付前**：跑校验器，把 FAIL 全部清零、WARN 逐条给理由。

```bash
python cmis-skill/tools/cmis_check.py cases/xxx.md
```

## 0.1 编号规则（两种编号，不要混）

| 编号 | 形态 | 含义 | 举例 |
|------|------|------|------|
| **依据条目号** | `D{册}-{两位}` | 一条**判断**，要被引用 | `D2-05 痛点明确 → 至少一款产品专门解决它` |
| **字段号** | `{章}-{两位}` | 一个**格子**，要被填写 | `3-06 审美权重表` |

> 字段号用于本文件检索与校验器定位；依据条目号用于方案内的引用闭环。**`2-01` 是"第 2 章第 1 个格子"，`D1-01` 是"D1 册第 1 条判断"，两者无关。**

## 0.2 必填等级

| 符号 | 含义 |
|------|------|
| ● | 全案必填（D-day ≥ 60） |
| ◐ | 标准案及以上（≥ 30 天） |
| ○ | 精简案及以上（≥ 15 天） |
| △ | 仅全案，或条件触发（如"多场连开才需要"） |

裁剪规则见 `decision-basis.md` §10；**○ 级以下的字段是"越紧急越不能删"的那批**，删了就只剩报价单。

## 23. 符号系统拦截条款（v6.0，Gate A/B 硬约束）

> 凤凰传奇案的教训：IP 强度 9.0、场馆稀缺 9/10、合作确定性 14/15——**三项全绿仍卖不动**。
> 缺的是第四个维度：这批粉丝的情感能不能装进一件东西里。以下三条不得跨越。

| # | 触发条件 | 强制动作 | 违反后果 |
|:---:|---|---|---|
| **S1** | `O < 0.4` 且 `τ < 180 天` | 形象类 / 娃类 / 多角色盲盒**一律不得进入矩阵**；改走声音实体化 / 行为凭证化 / 歌词文本化 | Gate A 不通过，退回重做矩阵 |
| **S2** | `f ≤ 0.7`（首次做实体周边） | SKU 数下调一档 + **必设 ¥15-35 入门件**（9-12）+ 重报预算 | Gate A 不通过 |
| **S3** | 任一 SKU 未能通过**可替换性检验**（9-11 判定 🔴） | 不得出现在主推位；降为补充款或剔除 | Gate B 判定失败 |

**连带效应（不可忽略）**：

- 命中 S1 → 圈层应改判为**传唱/集体释放型**，参数随之改为 `w 0.10-0.16`、`λ 0.85-1.0`、人均件数 1.1-1.4（`artist-archetypes.md` §二.5）
- `λ ≤1.0` 时**不设返单**（`quant-model.md` §四备注），预算与注意力全部压现场转化，而非"少备等补"
- 复盘归因时须按**四误差源**（总量/结构/长尾/**符号**）而非三源（`quant-model.md` §六）

> 写方案时把这三条当成"出门前摸口袋"：手机、钥匙、钱包——**O/τ/α/f 算了吗，S1-S3 过了吗，入门件有了吗。**

## 24. 价值捕获拦截条款（v6.1，Gate 0 / Gate A 硬约束）

> 周杰伦案的教训：近 20 万人次、上座率 100%，**6/27 周边遭哄抢、多个售卖点被抢空、派出所介入**，
> 钥匙扣被黄牛炒到 ¥399——一个被抢空的市场，却被业务侧按"卖得不好"归因。
>
> 以下条款针对两类错误：(a) 把②类"不够卖"当①类"卖不动"去重做产品；(b) 明知 V 极低仍按零售模型报价。

| # | 触发条件 | 强制动作 | 违反后果 |
|:---:|---|---|---|
| **V1** | 复盘/归因时出现"卖得不好""销量不佳"等表述 | 先做**口径核对**（Gate 0）：给出售罄率、有无抢购/哄抢、二级溢价三项证据；三者任一成立 → **自动归类为②不够卖，禁止进入"需求/产品"类处方** | 归因作废，重来 |
| **V2** | `V < 0.30` | 商业模式必须调整，并在合同中写明"我方流水受限于 N 个并行主体" | Gate A 不通过（按零售报价的版本） |
| **V3** | `V < 0.15` | 🔴 **不得按零售模型报价**。改保底+分成 / 渠道服务费 / 联合署名 / 代工供货 | Gate A 不通过；按 C13 判定为跨章冲突 |
| **V4** | 且命中 V1 的②类（供给不足） | **禁止产品改版**。处方限定为：加首批量 + 补 ¥150-400 中间带 + 补 ¥600-1500 礼盒带 + 限量编号回收二级溢价 | 方案退回——这是把好项目改坏的最快路径 |
| **V5** | IP 成熟度 >3 年 **且** 已授权第三方 ≥50 家 | 按**饱和态**处理：常规限定款无效，必须三选一（独占时间窗 / 独占品类条款 / 独占编号稀缺） | `symbol-system.md` §二；否则 V_category 计算无效 |

**口径核对四分类（写在每一份复盘文档的第 1 页）**：

| | 判定证据 | 处方归属 |
|---|---|---|
| ① 卖不动 | 售罄率<60%、库存剩余、无二级溢价 | 回 `O/τ/f/s/k` 重算 |
| ② 不够卖 | 售罄率>95% / 提前售罄 / 哄抢 / 二级溢价>30% | **供给**：加货 + 提客单价 |
| ③ 没份额 | 我方售罄但全域流水大，V<0.3 | **商业模式** |
| ④ 归别人 | 全域流水大但计入他方财报 | **谈判 / 归属** |

> 一句话记住：**先看售罄率，再看几个货架，最后才看设计。**
> 顺序反了就会把一个被抢空的项目，当成失败项目重做一遍。
