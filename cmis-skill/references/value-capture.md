# 价值捕获：为什么"这场很火"和"你能赚到钱"是两件事

> 用途：回答一个此前从未被量化的问题——**这场 IP 衍生品的总盘子里，有多少归我们？**
> 读取时机：Gate A 之前（算 V）→ 首次复盘时（口径核对）→ 每次"卖得不好"的归因之前。
>
> **来源 v6.1**：周杰伦「龙拳·北京·嘉年华2026」鸟巢站。
> 3 场近 20 万人次、上座率 100%、10.6 万张票秒罄；6/27 暴雨**周边遭哄抢、多个销售点被"洗劫一空"、派出所介入**；黄牛把钥匙扣炒到 ¥399。
> 一个被抢空的市场，业务侧却在问"为什么卖不过其他明星"。
> 完整归因见 `cases/周杰伦_龙拳北京鸟巢站_价值捕获复盘.md`。

---

## 零、为什么需要这一层

CMIS 到 v6.0 为止，回答的是三个问题：
1. **能不能做成**（授权、工期、合规）
2. **能不能卖动**（w、s、λ、f、O、τ、α）
3. **做多少**（数量、毛利、盈亏平衡）

缺了第四个：
4. **赚到的钱有多少进我口袋**

周杰伦案把这个缺口暴露到无法忽视：**需求侧满分（抢空），供给侧组织度满分（六级售卖主体、统一编号、统一自提核销），但定制款环节依然"体感很差"。**
三个变量全部满分，仍然亏。因为它从头到尾没问过第四件事。

## 一、第一步永远是口径核对：四种"卖得不好"

> **处方开错，比不开更贵。所以归因之前，必须先判定这是哪一种"不好"。**

### 判定树

```
Step 1  我方售罄率？
        ├─ <60% 且有库存剩余，且无线上二级溢价  →  ① 卖不动
        └─ >95%，或提前售罄                     →  不是①，进 Step 2

Step 2  是否存在抢购/哄抢/排长队抢空？或二级市场溢价 >30%？
        ├─ 是                                  →  ② 不够卖（供给不足）
        └─ 否                                  →  进 Step 3

Step 3  同 IP、同场次的全域流水是否远大于我方？
        ├─ 是，且我方在其中一个分流主体里       →  ③ 没份额
        └─ 是，且全域流水根本不进我方财报       →  ④ 归别人
```

### 四类处方（完全不同，不可混用）

| 类型 | 本质 | 处方 | **绝对不要做的事** |
|---|---|---|---|
| **① 卖不动** | 需求或产品不成立 | 回到 `O / τ / f / s / k` 重算；查品类结构与客单价结构 | 不要打折、不要加 SKU——会稀释定位且无效 |
| **② 不够卖** | **备货决策失败** | 提高首批量；补**中间带（¥150-400）与礼盒带（¥600-1500）**；用限量编号把二级溢价收回来 | **不要改设计**——设计不是问题 |
| **③ 没份额** | **商业模式选错** | 报价结构改为**保底 + 分成 / 渠道服务费 / 独占条款**；或主动做他方的供货方 | 不要继续优化产品去喂养一个注定亏损的结构 |
| **④ 归别人** | **权利归属问题** | 谈判：争取全域独家、联合署名、或分段归因；否则转为代工/供货 | 不要拿自己那一段业绩去评价整个项目的成败 |

### ⑤ 第五种：看错了

把 ②、③ 当成 ① 去"优化产品"，是四种错里**最贵的一种**：
它会让一个本来只是备货不足的项目，被整体重做成另一个更难卖的项目——而且是打着"上次数据不好"的名义。

> **规则：任何"销量不好"的结论，必须附上证伪它的证据。**
> 尤其必须查：是否有抢购/售罄/二级溢价。查到任一条，**① 自动排除**。

### 周杰伦案落点

| | 判定 | 证据 |
|---|---|---|
| ① 卖不动 | ❌ 排除 | 6/27 哄抢、多点被抢空、派出所介入 |
| ② 不够卖 | ✅ 成立 | 二级溢价 ¥399；官方措辞反复"售完即止" |
| ③ 没份额 | ✅ 成立 | 现场 6 个并行官方主体，单点上限 1/6 |
| ④ 归别人 | ✅ 成立 | ETERSOURCE 收藏卡 ¥350×11.8万盒通道；PHANTACi 客单价 ¥262-672 |
| **综合** | **②③④ 混合，此前被误判为 ①** | — |

## 二、V｜价值捕获率（Value Capture Ratio）

### 定义

```
V = 我方可捕获的流水 ÷ 同期同场景该 IP 衍生品全域流水
```

**四个分量，取最短板**（不连乘）：

```
V = min(V_pos, V_price, V_window, V_category)
```

> **为什么取短板而不是连乘**：四个分量捆绑在同一批人、同一个钱包上，彼此高度相关。
> 连乘会系统性低估到失去解释力的量级；**实际约束永远是"最紧的那一条"**（木桶原理）。

### 四个分量

| 分量 | 定义 | 算法 | 周杰伦案取值 |
|---|---|---|---|
| **V_pos 位置份额** | 我方在现场官方售卖主体中的份额 | 现场并行**官方主体数 n** → 单点上限 `1/n`；再按品牌力加权（自有潮牌/上市公司 IP 权重高） | n=6 → 上限 0.17，加权后 **≈0.13** |
| **V_price 客单价系数** | 同样的人流，能收到多少钱 | `我方客单价 ÷ 同场最强主体客单价` | ¥60 ÷ ¥400 ≈ **0.15-0.25** |
| **V_window 时间份额** | 我方窗口在 IP 全域活动中的占比 | `演出日天数 ÷ 全域活动天数` | 3 ÷ 23 ≈ **0.13** |
| **V_category 品类剩余率** | 拟做品类中未被常年授权覆盖的比例 | `1 − 已被常年授权的品类数 ÷ 拟做品类数` | 200+ 授权覆盖主要品类 → **0.3-0.5** |

> **V ≈ min(0.13, 0.20, 0.13, 0.4) ≈ 0.10-0.15**

### 分档与商业模式判定

| V | 等级 | 含义 | 应该采用的商业模式 |
|---|---|---|---|
| **≥0.50** | 🟢 主控 | 我方就是主要收款方 | 常规零售，标准零售预期 |
| **0.30-0.50** | 🟡 需争取 | 位置对了但被人分食 | 谈**独占时间窗**或**独占品类**条款 |
| **0.15-0.30** | 🟠 被动 | 结构性处于劣势 | **保底 + 分成**；或只做供货方 |
| **<0.15** | 🔴 **无零售空间** | 单点零售在数学上就不成立 | **不要接单点零售。**改谈渠道服务费 / 联合署名 / 代工供货 |

> **Gate A 新增硬条款**：`V < 0.15` → **不得按零售模型报价**。
> 必须改为保底+分成或服务费结构，或在合同中写明"我方流水受限于 N 个并行主体"。
> 这是周杰伦案的核心教训：**问题不是执行不好，是模式一开始就不该这么选。**

### 提高 V 的四条路（按顺序试）

| 动作 | 提升哪个分量 | 难度 |
|---|---|---|
| 谈**品类独占条款**（排除其他主体做同品类） | V_pos / V_category | 高，但收益最大 |
| 争取**场馆内外全域经营权**（不只是场内摊位） | V_window / V_pos | 中高 |
| 补**¥150-400 中间带 + ¥600-1500 礼盒带** | V_price | **低，最容易做** |
| 把销售窗**前移到预售、后移到演后**（拉长到 IP 活动全程） | V_window | 中 |

> 注意最后两条：**它们不需要谈判，只需要决策。**
> 周杰伦案里 V_price（0.15-0.25）是最便宜却没被使用的杠杆——货架最高单价只有 ¥128。

## 三、强 IP 的窗口重定义（v6.1）

CMIS 一直默认：**演唱会文创的销售窗口 = 演出当天 × 场馆内**。
周杰伦案证明，当 IP 成熟度足够高时，这个假设会崩塌：

| IP 成熟度 | 实际销售窗口 | 规划口径 |
|---|---|---|
| 弱 / 首次周边化 | 演出当天 × 场馆内 | 按默认口径 |
| 中等（有 IP 但授权有限） | 演出前后 1-2 周 × 场馆 + 线上 | 预售 + 演后补票窗口 |
| **强 IP（τ>3年 且 授权商>50家）** | **全城 × 全月 × 全渠道** | **必须按全域活动口径规划**：点位数、活动天数、长期店、线上通道 |

> 判定信号：检索"[艺人名] + [城市名] + 文旅/快闪/大娃/地标/限定"。
> 只要出现这类**城市级配套活动**，就按强 IP 窗口处理，否则会严重低估分流、高估单点销量。

## 四、与其他变量的关系

| 变量 | 分工 | 会不会重复打折 |
|---|---|---|
| `k` 分流率 | 折"钱花到别处"（其他品类、自带货） | 不重复：k 折全民的心智份额，V 折**同一批衍生品预算里的归属** |
| `f` 首次周边化 | 折"没有这个消费习惯" | 不重复 |
| `O/τ/α` | 折"符号本身成不成立" | 不重复 |
| **V** | 折"**赚到了但不在我这**" | — |

```
我方流水 R_mine = 全域衍生品流水 R_total × V
而  全域流水 R_total = N × w × k × f × 客单价 × λ
```

> **两条链要分开算**：先算"这场总共能卖多少"，再算"其中多少归我"。
> 混在一起算，是过去所有"卖得不好"误判的来源。

## 五、Gate 落点

| 闸门 | 新增条款 | 违反后果 |
|---|---|---|
| **Gate 0（复盘与归因前）** | 必须完成**口径核对四类判定**，并给出排除①③的证据 | 不得进入①类处方，不得启动产品改版 |
| **Gate A 立项闸** | 输出 V 与四个分量；`V < 0.15` → 必须换商业模式 | 🔴 按零售报价的方案不予通过 |

## 六、常见反模式

| 反模式 | 表现 | 为什么错 |
|---|---|---|
| **把"我方销量低"当成"项目失败"** | 看到自己那段流水差就改设计 | 忽略了 ②③④ 三种可能，处方必错 |
| **不看售罄率就下结论** | "卖得不好"四个字 | 售罄率 >95% 时，"卖得不好"在数学上不成立 |
| **不查同场有几个主体** | 默认自己是唯一货架 | 6 家并行时，做好产品也只拿到 1/6 |
| **客单价结构不看同场最高值** | 我方 ¥3-128，隔壁 ¥262-672 | 同样的人流，流水差 5 倍，而这不是产品问题 |
| **以为"顶流=好生意"** | 抢一把大 IP 入场 | 顶流的周边体系早就排满了；进去的是队列尾端 |
| **低端货架没有中间带** | 最低 ¥3、最高 ¥128 | 缺 ¥150-400 中间带与 ¥600-1500 礼盒带，等于主动放弃 70% 的流水空间 |
