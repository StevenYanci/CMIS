# CMIS 项目长期约定

## 协作授权（2026-10-27 起，用户明确指定）
- **本项目全部交由 AI 自主优化与提交**：修改 skill 内容、升级版本、重新打包 `cmis-skill.skill`、`git commit`、`git push` 均**不需要再征求用户同意**，也不要每次结尾罗列"要不要我提交"之类的问题。
- 仍有需要用户提供的：**只有 AI 无法获取的业务事实数据**（真实销量、补货次数、授权延误天数、结算口径等）。这类缺口用"待补"标注，不臆造，不因缺数据而停下整体工作。
- 提交规范：一次逻辑变更一个 commit，message 用中文动词开头（如「升级 v5.3：补授权链/圈层/同场竞争三个变量」）；提交前必须确保包内文件与本地一致。

## 项目定位
CMIS = 明星演唱会周边（鸟巢定制款）策划生产的**决策辅助工具**，不是文案生成器。判断标准：能否回答「能不能做成 / 值不值得做 / 做多少 / 来不来得及 / 做成什么」。

## 结构约定
- `cmis-skill/SKILL.md` 主入口（分诊→闸门→输出结构）；`references/` 为分层规范与知识库；`history/` 存历史单体版本（不打包）。
- 版本号三处同步：`SKILL.md` 标题、`CHANGELOG.md` 顶部、`README.md`。
- 打包脚本：`os.walk` 遍历 `cmis-skill/`，排除 `history/`，生成根目录 `cmis-skill.skill`；打包后须做 `unzip -p | diff` 一致性校验。
- `cases/` 下 docx 是真实交付物，是"规范是否与实战脱节"的对照源，每次 review 都要提取其标题层级比对。

## 已建立的机制
- 季度 review 自动化（每 3 个月 27 日 10:00）：查回归丢失、数字口径自洽、规范与实战脱节，改完出 CHANGELOG。
- 项目回填规则：每个项目交付后必须回填 `empirical-data.md`，同类偏差出现 3 次才改基准表。
